\section{Introduction}
\planned{One page.  The task: lossless compression of three standard
files under the strictest rules in use --- the program must reproduce
the file exactly, learning only from bytes already transmitted, and
the size of the decompressor counts.  The claim of the paper: a
single design principle --- every predictor is a Bayesian mixture,
every combination weight a posterior, every family of memory
structures generated rather than designed --- carried from a published
memoryless foundation to full sequential codes, lands at [FINAL
NUMBERS] on text8/enwik8/enwik9, placed against the published lists.
One paragraph on what is deliberately absent: no gradient-trained
mixing networks, no hand-designed context sets, no tuning on the test
files beyond the posterior mechanism itself.}

\section{The method in one section}
\planned{Two pages, plain language, no derivations.  (i) Tokens and
full fidelity: word tokens plus an escape mechanism; each new word
spelled once by a character-level code of the same construction;
every bit of the conversion measured, none estimated.  (ii) The
per-state estimator: the layered mixture over distribution
complexities [CITE companion paper]; one sentence on why it beats KT
on sparse rows, with the measured ablation number.  (iii) Memory:
families of state maps --- pooled context alphabets, context trees on
pooled histories, lag pools --- each family generated by a simple
rule, averaged under a posterior; the data selects resolution, depth
and range.  (iv) Sequential coding: predictive tables refreshed at
checkpoints, valid code, staleness measured.  Forward references to
the appendices for everything quantitative.}

\section{Results}
\planned{The core.  Organised by ACCOUNTING REGIME rather than by
tokenizer, because that is the real distinction: what does the
representation cost, and who pays for it?

\emph{(a) Bytes.}  No representation cost; everything is in the model.
Complete, self-contained, comparable to every entry on the published
list.  DONE: text8 4.1235, enwik8 5.0802, enwik9 5.1565 bits/character
(memoryless; redundancy $\le 2\cdot10^{-5}$ at all three scales, which
also establishes that the per-state prior is free in the dense regime,
so later gains are attributable to memory).

\emph{(b) Our adaptive tokenizer} (TOKENIZER.md v3).  The
representation is built from the past, so its cost is paid inside the
code --- the spelling stream is exactly that cost --- and nothing is
shipped.  A valid benchmark entry.  DONE at $10^8$: all four switch
settings measured on enwik8, won by intern + conditioned at 3.1282
bpc, ahead of intern + folded 3.1413, compositional + conditioned
3.1902 and compositional + folded 3.2032; text8 2.2483.  Conditioning
the case stream on the token halves it (0.8711 $\to$ 0.4640 bits per
letter run) but is not free --- on text8, where every letter run is
lowercase, conditioning \emph{costs} 547{,}004 bits, so both models
are always evaluated and the cheaper one selected.  [RUN: the winner
on enwik9.]

\emph{(c) A standard LLM tokenizer} (cl100k\_base via tiktoken).  The
representation comes from outside.  Reported TWICE: with the
vocabulary charged (zipped size 776{,}019 bytes = 0.0621 bpc at
$10^8$ --- a valid entry) and with it excluded (the convention of
perplexity work --- an LLM-comparability line, not an entry).  One
stream, fixed alphabet, no escape, spelling or case machinery: the
purest measurement of the estimator on a token sequence.  DONE at
$10^8$: text8 2.1716 charged / 2.1095 free; enwik8 2.9552 charged /
2.8931 free.  [RUN: enwik9.]

The comparison that (b) and (c) make possible, and whose sign we did
not know in advance, has come out \emph{against} adaptivity: the
pretrained vocabulary wins by 0.173 bpc on enwik8 even when charged
for.  The decomposition is the paper's point.  Our dictionary costs
0.1238 bpc and theirs 0.0621, so the accounting explains only a third
of the gap; the rest is segmentation.  cl100k\_base packs 3.877 bytes
into a token where our segmentation averages 2.405, because 63\% of
our segments are single ``other'' bytes --- the brackets, slashes and
quotes of XML, which BPE merges and we spend a symbol on each.  Even
with our spelling streams removed entirely we would sit at 3.004 bpc,
above the free BPE figure.  Two consequences for this paper: the
subword variant deferred in the specification is where the next
representation-level bit lives, and the markup bytes we currently
spend a token on are exactly the ones a context model should predict
almost for free, so this is the gap memory is most likely to close.

On top of the representation, the memory chain, currently measured on
text8 at $V$-capped scales: memoryless 1.8870 $\to$ complete first
order 1.7503 $\to$ pooled first order 1.6979 bpc; the lag pool adds
$0.064$ bits/token over the first-order expert and selects the
additive rule.  Remaining: [RUN: pooled-context tree, depth 3] $\to$
[RUN: multi-tier backoff] $\to$ [RUN: best structure as a sequential
code].  Placement against the published floor for each file: text8
paq8h 1.398 / durilca 1.417; enwik8 cmix 1.170 / durilca'kingsize
1.297; enwik9 nncp 0.858.

Note for the write-up: the combination rule deserves its own
treatment --- the additive/multiplicative dichotomy is a special case
of a more general scheme to be developed.}

\section{Reproducibility and the decompressor question}
\planned{The exact commands (from VERIFY.md) and the code reference.
The decompressor question, settled against the actual rules (checked
July 2026): the measured total is compressed size + a zip of the
decompressor and ``any other files needed at run time''; the
hardware, OS, compiler and language implementation are FREE provided
they are general purpose, public, and not designed for the ranking;
there are NO time or memory limits.  Consequences: (i) a
Python+numpy decompressor is admissible (general-purpose, contains
no knowledge of the data) --- a small native program is only the
conservative variant; (ii) the moment-table store costs nothing:
it is pure mathematics computed from no data, so the decompressor
REGENERATES it at run time and only the generating code is zipped
and counted; (iii) what must never appear in the free part is
anything with knowledge of the data --- the rules name dictionaries
as the canonical counted item.  Current status: numbers in this
paper are exact codelengths of decodable schemes; the packaged
encoder/decoder pair is deferred [agreed July 2026] until Stage A
settles the text8 structure.}
