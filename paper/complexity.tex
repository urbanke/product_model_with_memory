\noindent
Every experiment in this project is assembled from eight
computational tasks.  This note describes each task in a fixed
format: what the task is, the formula it evaluates, its inputs and
outputs --- and then, clearly separated, two parts: \emph{What is
implemented} (the algorithm that runs today, with measured costs)
and \emph{What could be done} (ideas that are not implemented yet,
each with its expected gain).  An idea that would give identical
results is marked [exact]; one that introduces a controlled error is
marked [approx].  The note ends with a discussion of the programming
language and a concrete plan for running the corpus enwik9.
Section~\ref{sec:defs} defines all concepts and symbols; nothing is
used before it is defined there.

\section{Definitions}
\label{sec:defs}

\field{The data}
Fix a finite set $\mathcal{A}$, the \emph{alphabet}, with
$|\mathcal{A}| = d$ elements, called \emph{symbols}.  The data is a
sequence $x_1, x_2, \dots, x_n$ with every $x_t \in \mathcal{A}$.
In our experiments a symbol is an English word, and the sequence is
the corpus \texttt{text8} with $n = 1.7 \cdot 10^7$ words;
depending on the experiment, $d$ ranges from $256$ to the full
number of distinct words, $253{,}855$.

\field{States}
A \emph{memory rule} consists of a finite set $\mathcal{S}$ of
\emph{states} and a map $\sigma$ that assigns a state to every
sufficiently long sequence of symbols.  Three rules are used in this
project:
(a)~$\sigma(x_1, \dots, x_{t-1}) = x_{t-1}$, the last symbol; here
$\mathcal{S} = \mathcal{A}$;
(b)~$\sigma(x_1, \dots, x_{t-1}) = (x_{t-2},\, x_{t-1})$, the last
two symbols; here $\mathcal{S} = \mathcal{A} \times \mathcal{A}$;
(c)~$\sigma(x_1, \dots, x_{t-1}) = x_{t-\delta}$ for a fixed
integer $\delta \ge 1$, the symbol $\delta$ positions back (we
call $\delta$ the \emph{lag}); here $\mathcal{S} = \mathcal{A}$.
For a position $t$ we abbreviate
\[
  s_t \;:=\; \sigma(x_1, \dots, x_{t-1}) \;\in\; \mathcal{S}.
\]
The notation hides the arguments, so let us state them: $s_t$ is a
function of the symbols at positions $1, \dots, t-1$ and of nothing
else; in particular it does not depend on $x_t$, because $s_t$ will
be used to predict $x_t$.  A rule may be undefined when the sequence
before $t$ is too short (rule (c) needs at least $\delta$ preceding
symbols).  Let $t_0$ denote the first position at which the rule is
defined ($t_0 = \delta + 1$ for rule (c), $t_0 = 3$ for rule (b));
then $s_t$ exists exactly for $t = t_0, \dots, n$, and these are the
positions the experiment codes.  When several rules are used in one
experiment, $t_0$ is the largest of their individual starting
positions, the same for all models compared.

\field{Count rows}
For each state $s \in \mathcal{S}$ and each symbol
$x \in \mathcal{A}$ define
\[
  m_x(s) \;=\; \#\bigl\{\, t \in \{t_0, \dots, n\}
  \;:\; s_t = s \ \text{ and }\ x_t = x \,\bigr\},
\]
that is: among the coded positions $t$ whose state $s_t$ equals $s$,
the number $m_x(s)$ counts those at which the symbol $x$ occurred.
The vector $m(s) = \bigl(m_x(s)\bigr)_{x \in \mathcal{A}}$ is
called the \emph{row} of the state $s$.  Under rule (a), for
instance, the row of the state $s = \textit{the}$ records, for
every word $x$ of the vocabulary, how many times $x$ occurred
immediately after \emph{the} in the corpus.  For one fixed row we
write $N = \sum_{x} m_x(s)$ for the sum of its entries (equivalently
the number of coded positions with state $s$), $k$ for the number of
its nonzero entries, and we call a symbol \emph{observed} in the row
if its entry is nonzero.

\field{Profiles}
The \emph{profile} of a row is the list of its nonzero entries,
sorted in increasing order, with the identities of the symbols
discarded.  For example, the row $(0, 3, 0, 1, 1)$ has the profile
$(1, 1, 3)$.  We write a profile as $\prof = (m_1, \dots, m_k)$ with
$0 < m_1 \le \dots \le m_k$.  Two further quantities of a profile
matter for costs: $\tilde k$, the number of \emph{distinct} values
among its entries (the example has $\tilde k = 2$: the values $1$
and $3$), and the multiplicity $\mu_c$ of each distinct value $c$
(here $\mu_1 = 2$, $\mu_3 = 1$).

\field{The probability model}
All experiments use one probability model for the coded symbols; the
compressed length is, as always, $-\log_2$ of the probability this
model assigns to the data.  The model has three ingredients.

First: \emph{given} a probability vector for every state, symbols
are independent draws.  Suppose for a moment that every state $s \in
\mathcal{S}$ came with a known probability vector $p(s) =
\bigl(p_x(s)\bigr)_{x \in \mathcal{A}}$.  The model then says:
at each coded position $t$, the symbol $x_t$ is drawn from the
vector of the current state, $p(s_t)$, independently of everything
else.  Under this assumption the probability of the whole coded
sequence $x_{t_0}, \dots, x_n$ factorizes into one factor per
state, and the factor of state $s$ depends only on that state's
row:
\begin{equation}
  \prod_{t = t_0}^{n} p_{x_t}(s_t)
  \;=\; \prod_{s \in \mathcal{S}}\;
  \prod_{x \in \mathcal{A}} p_x(s)^{\,m_x(s)} .
  \label{eq:factorize}
\end{equation}

Second: the vectors $p(s)$ are not known, so the model treats them
as random and \emph{averages} over them (this is the Bayesian
mixture).  The vectors of different states are drawn independently,
each from the same prior distribution on the set of probability
vectors; the prior is defined next.  Averaging
Eq.~\eqref{eq:factorize} over these independent draws keeps the
product over states:
\begin{equation}
  P(\text{coded sequence})
  \;=\; \prod_{s \in \mathcal{S}}
  \;\mathbb{E}\Bigl[\, \prod_{x \in \mathcal{A}}
  p_x(s)^{\,m_x(s)} \Bigr],
  \label{eq:corpusprob}
\end{equation}
one expectation per state, each depending only on the state's row.
The total compressed length is $-\log_2$ of
Eq.~\eqref{eq:corpusprob}, i.e.\ a sum over states of per-row
contributions.  (So the model does not ``estimate'' a single
quantity; it assigns a probability to the data.  We nevertheless
speak of an estimator because the same construction, applied one
position at a time, turns counts into predictions: that is
Eq.~\eqref{eq:pred} of task T3.)

\field{The prior}
The prior over a probability vector is built in \emph{levels}.  At
level $L \ge 1$, attach to each symbol $x$ a random weight
\[
  W_x \;=\; E_{x,1} \cdot E_{x,2} \cdots E_{x,L},
\]
where the $E_{x,\ell}$ are independent random variables, each with
the standard exponential distribution (density $e^{-v}$ for $v >
0$), and set $p_x = W_x / (W_1 + \dots + W_d)$.  The distribution
of the vector $(p_1, \dots, p_d)$ obtained this way is the
\emph{level-$L$ prior} $\Pi_L$.  The larger $L$ is, the more
uneven the vectors drawn from $\Pi_L$ tend to be, so $L$ acts as a
roughness parameter.  The model does not choose a level; the prior
actually used is the uniform average
\[
  \Pi \;=\; \frac{1}{L_{\max}} \sum_{L=1}^{L_{\max}} \Pi_L,
  \qquad L_{\max} = \lceil 2 c^{*} \ln d \rceil,\;\;
  c^{*} \approx 2.365
\]
($c^{*}$ is a constant from the companion paper; in our runs
$L_{\max}$ is between $33$ and $59$).  This average over levels is
the second averaging in the model; each state's vector is drawn from
$\Pi$, independently across states.

\field{The central quantity}
The expectation in Eq.~\eqref{eq:corpusprob}, evaluated for one
state, is the number everything else computes.  Two simplifications
reduce it to a function of the profile alone.  Because $\Pi_L$
treats all symbols symmetrically (it is exchangeable), the
expectation does not depend on \emph{which} symbols carry the
nonzero counts --- only on the profile $\prof$ of the row.  And
because $\Pi$ is an average, the expectation under $\Pi$ is the
average of the expectations under the $\Pi_L$.  So define, for a
profile $\prof = (m_1, \dots, m_k)$,
\begin{equation}
  q_L(\prof) \;=\; \mathbb{E}_{p \sim \Pi_L}
  \Bigl[\, p_{y_1}^{\,m_1} \cdots p_{y_k}^{\,m_k} \Bigr]
  \quad (y_1, \dots, y_k \text{ any distinct symbols}),
  \qquad
  q_{\mathrm{avg}}(\prof) \;=\; \frac{1}{L_{\max}}
  \sum_{L=1}^{L_{\max}} q_L(\prof).
  \label{eq:qdef}
\end{equation}
With this notation, the total compressed length of a model with
states $\mathcal{S}$ is exactly
\[
  \sum_{s \in \mathcal{S}} -\log_2
  q_{\mathrm{avg}}\bigl(\text{profile of } m(s)\bigr).
\]
Rows with equal profiles contribute equal terms, so every
computation first deduplicates rows by profile; in our runs this
shrinks the workload by a factor of $50$ to $100$.

\field{The integral form}
Eq.~\eqref{eq:qdef} is an expectation over $d$ random weights; to
compute it we turn it into a one-dimensional integral.  The
denominator $(W_1 + \dots + W_d)^N$ is removed with the identity
$A^{-N} = \frac{1}{\Gamma(N)} \int_0^\infty t^{N-1} e^{-tA}\, dt$
(valid for $A > 0$; here $t$ is a real integration variable, a
scalar).  After this substitution the expectation splits into a
product of one factor per symbol, because the weights of different
symbols are independent.  The result is exact:
\begin{equation}
  q_L(\prof) \;=\; \frac{1}{\Gamma(N)} \int_0^{\infty} t^{N-1}\,
  \varphi^{(L)}_0(t)^{\,d-k}\,
  \prod_{i=1}^{k} \varphi^{(L)}_{m_i}(t)\; dt,
  \label{eq:integral}
\end{equation}
where the function $\varphi^{(L)}_r$, which we call the
\emph{moment function}, is defined by
\begin{equation}
  \varphi^{(L)}_{r}(t) \;=\; \mathbb{E}\bigl[\,Y^{\,r}\, e^{-tY}
  \bigr],
  \qquad Y = E_1 E_2 \cdots E_L
  \label{eq:phidef}
\end{equation}
with $E_1, \dots, E_L$ independent standard exponentials.  In words:
$Y$ is a product of $L$ independent exponential random variables, and
$\varphi^{(L)}_r(t)$ is the expected value of $Y^r e^{-tY}$ --- a
function of the single real argument $t \ge 0$, one such function for
each pair $(L, r)$.  The factor $\varphi^{(L)}_0(t)^{d-k}$ in
Eq.~\eqref{eq:integral} collects the $d - k$ symbols that are not
observed in the row (their count is $r = 0$).

\field{The computational axis}
All numerics happen on the logarithmic axis $u = \ln t$ ($u$ is a
scalar), restricted to a finite grid $u_1 < u_2 < \dots < u_G$; in
the largest runs $G = 3.6 \cdot 10^4$.  Taking logarithms of the
integrand of Eq.~\eqref{eq:integral} and substituting $t = e^u$
gives the \emph{log-integrand}
\begin{equation}
  \psi_L(u) \;=\; N u \;+\; (d - k) \ln \varphi^{(L)}_0(e^u)
  \;+\; \sum_{\text{distinct values } c \text{ of } \prof}
  \mu_c \ln \varphi^{(L)}_c(e^u),
  \label{eq:psi}
\end{equation}
so that $q_L(\prof) = \frac{1}{\Gamma(N)} \int_{-\infty}^{\infty}
e^{\psi_L(u)}\, du$.  Two exact facts anchor the numerics.  First,
at level one the moment function has the closed form
$\varphi^{(1)}_r(t) = \Gamma(r+1) / (1+t)^{r+1}$, and the whole
integral at $L = 1$ reduces to a classical closed form (the
Dirichlet--multinomial); no numerics are needed there.  Second, as
$t \to 0$ the moment function tends to the constant
$\Gamma(r+1)^L$; therefore, to the left of the grid, $\psi_L(u) =
Nu + \text{const} + O(e^u)$, and the left tail of the integral is
available in closed form.

\section{T1 --- Building the tables of moment functions}

\field{Task}
Compute the moment functions $\varphi^{(L)}_r$ of
Eq.~\eqref{eq:phidef} numerically, for every level
$L \le L_{\max}$ and every count value $r$ that occurs in the data,
and store their logarithms on the $u$ grid.  The stored tables are
read by tasks T2 and T3.

\field{Formula}
Three exact representations are used, each in the region where it is
reliable: for small $t$ the alternating series
$\varphi = \sum_j (-t)^j\, \Gamma(r{+}j{+}1)^L / j!$; in the middle
the contour integral
$\varphi = \frac{1}{2\pi i}\int \Gamma(z)\, t^{-z}\,
\Gamma(r{+}1{-}z)^L\, dz$; for large $t$ the residue series at the
poles $z = r{+}1, r{+}2, \dots$ (powers of $1/t$ times polynomials
in $\ln t$).

\field{Input and output}
In: the set $\mathcal{R}$ of count values in the data, the number of
levels $L_{\max}$.  Out: the numbers
$\ln \varphi^{(L)}_r(e^{u})$ on a fixed grid of $u$ values with
spacing $0.02$, stored on disk, one file per level.

\field{What is implemented}
One \emph{permanent store}, shared by all experiments and grown on
demand: the first computation that needs a value computes and files
it; every later computation reads it.  Each stored value comes from
one of the three exact formulas above, used only where it can
certify its own error; the three regions overlap and the methods
agree there to $10^{-8}$ or better, checked also against Monte Carlo
simulation in the one corner where nothing else reaches.  Queries
between grid points are answered by degree-$7$ interpolation (linear
interpolation would cost whole nats at large counts, cubic
$\sim 10^{-5}$; both measured).  Columns are built on all processor
cores; to save time, a column is computed exactly only at every
fourth grid point and filled in between by the same degree-$7$ rule
--- \emph{except} where an eighth-difference test says the fill
cannot reach $10^{-8}$ (those points are computed exactly), and
random spot checks against exact values guard the whole column, with
a full exact rebuild on failure.

Two more implemented savings, both pure Python.  First, nearby grid
points share one vertical contour and ONE set of $\ln\Gamma$
evaluations --- the expensive factors do not depend on the grid point
$u$, only the cheap exponential does.  Second, the large-$t$ residue
series is evaluated for a whole column at once instead of point by
point; profiling on deep columns showed the point-by-point loop
consuming $76$--$99\%$ of their build time (a lesson in measuring
the right workload: the contour saving alone showed no end-to-end
gain there).  Measured on deep columns: $0.5$ s $\to$
$0.02$--$0.14$ s each; in the running V$=256$ build, throughput rose
from $\sim 20$ to $\sim 250$ columns/s on $12$ cores.

Measured accuracy, end to end (what a query actually receives): over
$900$ random off-grid checks against the independent reference,
median error $7\cdot 10^{-14}$ nats, maximum $2.4\cdot 10^{-7}$ ---
and the maximum occurs only where the value itself is $\sim 10^9$,
i.e.\ at the resolution limit of $64$-bit numbers.  Measured cost
(after all savings): $0.01$--$0.15$ s per column on one core, size
dependent; a first V$=256$ paper run needs $\sim 1.6\cdot 10^5$
columns, all reused by every later run.  Storage: $\sim 60$ kB per
column.

The previous builder (a level recursion with fixed-node quadrature,
rebuilt per run) was replaced because certification showed it wrong
in two regions: harmlessly at the far right of the grid, and
destructively at the far left for counts $\gtrsim 360$ --- tens to
hundreds of nats per value, growing with depth, reaching real
codelengths at the $5\cdot 10^{-3}$ bits-per-profile scale already
at count $301$.  The verification reruns will quantify the effect on
the published numbers.

\field{What could be done}
(1)~[exact] A native-code kernel for the contour quadrature; part
of the once-projected $5$--$10\times$ is already captured by the
shared-line saving above, so the realistic remaining native gain is
$2$--$4\times$ (see the language section).
(2)~[exact] Coarser build strides where the eighth-difference test
permits them --- the machinery already measures exactly this.
(3)~[exact] Store in single precision: half the disk, error
$\sim 10^{-7}$ relative, still below everything that matters.
(4)~[exact] A repaired level recursion as a fast bulk builder for
small counts, admitted only where it agrees with the certified
methods (a first attempt is shelved: its quadrature window misses
the integrand peak at deep levels).

\section{T2 --- Evaluating the probability of one profile}

\field{Task}
Given one profile, compute $\log q_L$ for every level $L$, and from
these $\log q_{\mathrm{avg}}$.  This is the innermost computation of
the project; we call it the \emph{atom}.  A static model invokes it
once per distinct profile; a sequential model invokes it again at
every table refresh (T8).

\field{Formula}
Eqs.~\eqref{eq:qdef}--\eqref{eq:psi}:
$\log q_L(\prof) = \log \int e^{\psi_L(u)}\,du \;-\; \ln \Gamma(N)$.

\field{Input and output}
In: the profile (distinct values $c$ with multiplicities $\mu_c$)
and the tables of T1.  Out: the vector
$\bigl(\log_2 q_L(\prof)\bigr)_{L = 1..L_{\max}}$ and the average.

\field{What is implemented}
Per level: (i)~assemble the log-integrand $\psi_L$ on the grid from
$\tilde k + 1$ table rows, $O(G \tilde k)$ additions; (ii)~find all
local maxima within a fixed window below the global one (the
integrand can have two peaks); (iii)~refine each maximum by a
bracketed solve and add the peak contributions by Laplace's method;
(iv)~add the closed-form left tail.  Profiles with $N \le 1$ and the
level $L = 1$ come from closed forms.  Batches of profiles run in
parallel: profiles are split over worker processes, and each level's
table rows reach the workers through shared memory (important on
network file systems).  Step (i) dominates: $O(L_{\max} G \tilde k)$
per profile.  Measured: $7\cdot 10^4$ distinct profiles at
$L_{\max} = 59$ in $17$ minutes on $64$ cores.

\field{What could be done}
(1)~[exact] \emph{Remember where the peaks are.}  The full grid
sweep exists only to locate the maxima.  They move very little when
a profile changes slightly (in particular between refreshes of the
same row); starting the solve from the stored location would replace
the sweep by a small window, potentially $\sim 300\times$ on
step~(i), with the full sweep as fallback.
(2)~[approx] \emph{Truncate the sum over levels}: a few levels
around the largest term carry the sum; evaluating those exactly and
bounding the rest replaces $L_{\max}$ by an effective $5$--$10$.
(3)~[approx] Coarser grids for small-$N$ profiles, chosen from a
target accuracy.

\section{T3 --- The prediction table of one row}

\field{Task}
Turn one row into a probability distribution for the symbol at the
next position.  This is the workhorse of the sequential codes of
T6--T8: at every refresh, every row of every predictor is converted
into such a table.

\field{Formula}
Let $\prof$ be the row's profile and let $c$ be the row's entry for
some symbol ($c = 0$ if the symbol is not observed in the row).
Write $\prof \oplus c$ for the profile obtained from $\prof$ by
increasing one entry with value $c$ by one (for $c = 0$: by
appending a new entry $1$).  The model's probability that the
next symbol is that particular symbol is
\begin{equation}
  p \;=\;
  \frac{q_{\mathrm{avg}}(\prof \oplus c)}{q_{\mathrm{avg}}(\prof)} .
  \label{eq:pred}
\end{equation}
The value depends on the symbol only through its count $c$, so the
table has only $\tilde k + 1$ distinct entries.

\field{Input and output}
In: the row's counts; the tables of T1.  Out: the logarithms of the
$\tilde k + 1$ distinct probabilities and the assignment of symbols
to them.

\field{What is implemented}
\emph{All ratios from one integrand.}  The profiles
$\prof \oplus c$ differ from $\prof$ in a single factor of the
integrand in Eq.~\eqref{eq:integral}:
\[
  q_L(\prof \oplus c) \;=\; \frac{1}{\Gamma(N+1)} \int
  e^{\psi_L(u)}\, \cdot\, e^{u}\,
  \frac{\varphi^{(L)}_{c+1}(e^u)}{\varphi^{(L)}_{c}(e^u)}\; du .
\]
The evaluator (the ``family'' evaluator) assembles $\psi_L$ once at
cost $O(G\tilde k)$ and derives every member by one $O(G)$ update
--- the cost per row fell from $O(G \tilde k^{2})$ to
$O(G \tilde k)$, a factor $\tilde k \approx 100$ on the rich rows
that dominate.  It was verified to reproduce the member-by-member
results \emph{exactly}, and all prediction tables now route through
it.  On top of this, results are memoized by profile: a profile seen
before (another row, another refresh) is never recomputed.

\field{What could be done}
(1)~[exact] \emph{Update the integrand instead of rebuilding it.}
Between two refreshes only a few entries of a row change; keeping
the row's $\psi_L$ in memory and adjusting the changed factors makes
the cost proportional to the number of changes, not to $\tilde k$.
Memory: $\approx 8$ MB per kept row at the largest settings ---
affordable exactly for the busy (expensive) rows.
(2)~The ideas of T2 apply on top.

\section{T4 --- Counting}

\field{Task}
Read the corpus once and produce, for a given state rule $\sigma$,
all rows, their profiles, and the assignment of each row to its
profile.

\field{Formula}
$m_x(s)$ as in Section~\ref{sec:defs}, for every state $s$ that
occurs; then profiles and deduplication.

\field{Input and output}
In: the corpus as $n$ integers; the rule $\sigma$.  Out:
$\mathcal{N}$ rows with $P$ nonzero entries in total; the list of
$U$ distinct profiles; the map from rows to profiles.

\field{What is implemented}
Counting by \emph{sorting packed keys} (implemented July 30): each
position's (context, next symbol) window is packed into fixed-width
integers, the packed keys are sorted, and every context's row is
then one contiguous run --- the same information a suffix array
exposes through suffix intervals, obtained with a few flat arrays of
size $n$.  Memory no longer depends on how many distinct contexts
exist.  Verified to agree \emph{exactly} with the previous
hash-table counting (synthetic data, a $10^6$-token text8 slice at
every depth), and on full text8 at full vocabulary, depth two, it
reproduces the cluster run to the digit ($4{,}400{,}703$ contexts,
$70{,}090$ distinct profiles).  Measured there: $25$ s and
$2.6$ GB peak --- against $\sim 200$ GB for the hash counting it
replaces.  Depths three and beyond work (keys spanning several
$64$-bit words are supported and tested).

\field{What could be done}
(1)~[exact] A full suffix array if unbounded depth is ever needed in
one pass; the sorted-key counting handles each depth separately,
which is enough for everything planned.
(2)~[exact] The per-context Python loop that deduplicates profiles
is the remaining (mild) cost at very large context counts; it can be
vectorized if it ever shows up in measurements.

\section{T5 --- Aggregation}

\field{Task and formula}
Assemble atoms into results: the total codelength
of a model, the mixture over a family of models, the posterior over
the family.
The length of one model is $\sum_{\text{rows}} -\log_2
q_{\mathrm{avg}}(\text{profile of the row})$.  For the context-tree
family the mixture over all prunings is computed by the recursion
$\beta(v) = \frac12 q_{\mathrm{avg}}(\prof_v) + \frac12 \prod_{w}
\beta(w)$, where $v$ runs over observed contexts, $\prof_v$ is the
row of $v$, and $w$ runs over the observed one-symbol extensions of
$v$.  The mixture over any finite family of $K$ models is the
log-sum-exp of their total log-probabilities minus $\log_2 K$.

\field{What is implemented}
Single passes over rows and contexts; cost $O(\mathcal{N})$ or
$O(P)$; measured in seconds.

\field{What could be done}
Nothing needed; this task is never a bottleneck.

\section{T6 --- Combining predictors by weighted sums}

\field{Task}
Given $D$ lag predictors and the no-memory predictor, code the
corpus under \emph{every} candidate weight vector of a grid
simultaneously, in one pass.

\field{Formula}
At position $t$, predictor $e$ supplies the probability $p_{e,t}$
it assigned to the symbol that actually occurred (read from its
current prediction table, T3).  For each weight vector $\lambda$ of
a grid of size $K$:
\[
  \mathrm{bits}(\lambda) \;=\; \sum_{t = t_0}^{n}\; -\log_2
  \Bigl(\, \sum_{e=0}^{D} \lambda_e\; p_{e,t} \Bigr).
\]

\field{What is implemented}
One matrix product of the $p$ array with the weight matrix per block
of positions, then logarithms: $O(n (D+1) K)$ multiplications,
$\sim 10^{10}$ at our settings --- minutes.

\field{What could be done}
Nothing needed; linear in everything.

\section{T7 --- Combining predictors by tempered products}

\field{Task}
The same as T6 for the multiplicative rule.  The product of
probabilities must be renormalized \emph{over the whole alphabet at
every position}, and this normalization is the expensive part.

\field{Formula}
Let $q_0$ be the no-memory predictor's table and $p_j(x)$ the
probability that lag predictor $j$ currently assigns to symbol $x$.
For an exponent vector $\beta$ from a grid of size
$K_{\mathrm{prod}}$:
\[
  p_\beta(x) \;=\; \frac{s_\beta(x)}{Z}, \qquad
  s_\beta(x) \;=\; q_0(x) \prod_{j=1}^{D}
  \biggl(\frac{p_j(x)}{q_0(x)}\biggr)^{\!\beta_j}, \qquad
  Z \;=\; \sum_{x=1}^{d} s_\beta(x),
\]
with $Z$ recomputed at every position.

\field{What is implemented}
Both forms.  The dense computation (the original path): at every
position, form the $d$ numbers $\ln s_\beta(x)$ and sum their
exponentials; cost $O(n\, d\, D\, K_{\mathrm{prod}})$, measured
$68$ minutes at $d = 4{,}096$ --- the only part of the project whose
cost is proportional to the alphabet size at every position.

And, since July 30, the SPARSE normalization that removes the factor
$d$: by Eq.~\eqref{eq:pred}, each prediction table has one shared
value for all symbols unobserved in the row.  Let $S$ be the union
of the observed-symbol sets of the $D$ current rows; outside $S$
every factor takes its shared value, so
$s_\beta(x) = (\text{const}) \cdot q_0(x)^{\gamma}$ with
$\gamma = 1 - \sum_j \beta_j$, and
\[
  Z \;=\; (\text{const}) \cdot \Bigl( T_\gamma +
  \sum_{x \in S} q_0(x)^{\gamma}\,
  \bigl(2^{\delta(x)} - 1\bigr) \Bigr),
  \qquad
  T_\gamma \;=\; \sum_{x=1}^{d} q_0(x)^{\gamma},
\]
with $\delta(x)$ the support corrections and the power sums
$T_\gamma$ computed once per refresh; the constant cancels against
the numerator.  Cost per position $O(|S| D)$ instead of $O(d\,D)$.
Verified to reproduce the dense evaluation to $10^{-14}$
bits per token on every member of the grid, including saturated rows
(handled by an arbitrary finite reference value, which the algebra
permits).  Selected automatically for $d > 4{,}096$.

\field{What could be done}
Nothing further needed for the planned corpora; the per-chunk
sorting that groups support entries could move to a compiled kernel
if it ever dominates.

\section{T8 --- Scheduling the refreshes of a sequential code}

\field{Task}
A sequential code reads the corpus once and predicts each position
from the counts gathered so far.  Recomputing every prediction table
at every position would be exact but hopeless; instead the tables
are \emph{refreshed} at chosen moments and used unchanged in
between.  Any refresh schedule that depends only on the past yields
a valid code; using slightly outdated tables only lengthens the
output a little.  The schedule determines how many times T3 runs.

\field{What is implemented}
A global clock: all rows are refreshed at $C$ evenly spaced
positions (measured: $5.9\cdot 10^6$ atom evaluations at
$d = 1{,}024$, $C = 32$).  On top of it, the memoization of T3 means
a refresh only pays for rows whose profile actually changed --- the
evaluation cost is already driven by growth, not by the clock.

\field{What could be done}
(1)~[valid code; staleness controlled; \emph{changes the coded
numbers}, so it is an experiment-design decision, not a drop-in]
\emph{Refresh on growth}: rebuild a row's table when its total has
grown by a factor $1+\epsilon$ since the last rebuild.  A row ending
at total $N$ is rebuilt $\log_{1+\epsilon} N$ times instead of $C$
times.
(2)~[exact] Distribute rows over cluster nodes; rows are independent
once the schedule is fixed.

\section*{The choice of language}

Everything is Python today.  The heavy inner loops already execute
inside NumPy's compiled kernels (C), so a wholesale rewrite in C,
Rust or Julia would mostly remove glue and gain little where the
arrays are long: the T2/T3 grid work, the T6/T7 member loops, and
the counting passes are of this kind (perhaps $1.5$--$3\times$ where
arrays are short).

Native code would pay in exactly two places.  First, the T1 column
builder, whose cost is complex $\ln\Gamma$ over quadrature lattices:
a tight compiled loop should give $5$--$10\times$ on the build.
Second, the per-peak refinement of T2, which is scalar Python (root
brackets, a few dozen calls per peak) and would compile well.  The
pragmatic route is a small compiled extension (Cython/Rust) or
just-in-time compilation (Numba) for these two or three kernels,
keeping orchestration, storage and certification in Python.  The
measurements do not justify more: parallelism and the algorithmic
ideas above dominate every observed bottleneck.

\section*{A plan for enwik9}

Target: enwik9 ($10^9$ bytes; roughly $1.4\cdot 10^8$ words, ten
times text8; a vocabulary of a few million distinct words; deepest
level $L_{\max} \approx 75$--$80$).  Hardware assumed: one machine
with $64$ cores, $256$ GB of memory, and $\sim 1$ TB of disk ---
i.e.\ one good cluster node.  Two numbers below are extrapolations
(marked *); both should be measured with a cheap counting pass
before anything is committed.

\begin{enumerate}
\item \emph{Counting (T4) --- DONE (July 30).}  The sorted-key
counting needs a few flat arrays of size $n$: measured $2.6$ GB on
full-vocabulary text8 at depth two; at enwik9 scale an estimated
$20$--$40$ GB transient, within the node.  The former $200$ GB
blocker is gone.

\item \emph{Tables (T1).}  Expected* $3$--$6\cdot 10^4$ distinct
count values, giving $2.5$--$5$ million columns over $\sim 80$
levels.  At the measured $0.01$--$0.15$ s per column per core this is
$10$--$100$ core-hours, i.e.\ under $2$ hours on the node; the
native kernel is no longer needed for this step.  Disk:
$0.2$--$0.5$ TB (half in single precision).  Built once, ever.

\item \emph{Static models (T2, T5).}  Expected* a few hundred
thousand distinct profiles per model.  The measured rate
($7\cdot 10^4$ profiles at $59$ levels in $17$ minutes on $64$
cores) extrapolates to a few hours per model; the remembered-peaks
idea (T2) would cut this several-fold.  So the static part of an
enwik9 paper --- memoryless, first-order, context trees --- is
node-hours, not node-days.

\item \emph{Sequential codes (T3, T6--T8).}  The sparse
normalization of T7 is implemented (the dense form would cost a
factor $d = 10^6$ per position).  With it, the family evaluator and
memoization, and a refresh schedule of $C \approx 32$, the
pooled-lag experiment extrapolates to a few node-days; the
refresh-on-growth decision (T8) and integrand updates (T3) would
bring it under one node-day.
\end{enumerate}

Order of work, then: (1)~counting --- done; (2)~sparse
normalization --- done; (3)~the native kernel for the table builder
and (4)~remembered peaks --- comfort.  Both prerequisites are in
place; nothing on this list requires more than the one node
described above.
